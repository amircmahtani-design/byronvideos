# Varied, source-supported motion — direction draft

**Status: DRAFT. Positive feedback on a short preview approves a direction only.
It does not approve an immutable visual style, final voice, or every generated action.**
The earlier still-image/contain presets are historical local prototypes, not the
intended finished aesthetic. Do not edit their frozen snapshots to erase history.
This protocol is a separate generated-motion extension for the portrait workflow;
it does not turn on a provider or rewrite the old renderer's no-AI invariant.

## Intent

Use portrait 9:16 imagery filling the video area. Each painting should feel alive
in a way appropriate to what is actually present—not always moving hair and
opening/closing eyes. Preserve original image bytes, identity, composition,
numbered upload order, exact narration, accepted caption treatment and story beats.
Generated derivatives remain private until separately selected for publication.

## Source-supported variety, not a random action rotation

- Consider visible environment movement (foliage, a curtain, water or clouds),
  a small settling of visible fabric, restrained changes from an existing light
  source, pose-preserving breathing/posture settling, or a bounded camera move.
- Choose only categories supported by a reviewed source-visible feature record
  for that exact image hash. Never invent curtains, water, light sources, gestures
  or interactions merely to create variety. Do not reorder paintings to vary them.
- Prefer a varied film-wide combination and avoid adjacent repetition when the
  available features permit it. Deterministically consider later scenes too, so
  an early choice does not unnecessarily force later repetition.
- Hair and natural blinking may be secondary details only. They cannot be the
  primary motion template repeated across all scenes. No repeated blink cycle,
  prolonged eye closure, GIF loop, frozen extension or replayed footage.
- A gesture must preserve the existing pose and relationship. No invented kiss,
  embrace, reaching, walking, speaking, new expression-led story event or other
  narrative action. When only one safe primary category is available, flag the
  limited variety for review rather than manufacturing something unsafe.

## Planning and verification

The machine source, this protocol and the planner implementation are hash-bound
into a compact runtime file. The worker reads that snapshot, not an LLM summary
of the prose. Every plan binds the snapshot, original image hashes, source-visible
feature review, unchanged input order and exact narration-text fingerprint.
Whitelisted source-feature descriptions produce a deterministic provider prompt;
raw script text and URLs cannot become prompt instructions. The plan carries
the exact compact policy snapshot so a worker cannot silently read newer settings.
Scene durations arrive from the existing narration/story-beat timing plan; this
extension does not divide the essay into arbitrary equal image blocks. The job
validator requires the independently supplied upstream timing snapshot as well as
the plan; it binds audio/word-time hashes and exact overlap/durations. This planner
does not itself decode that referenced audio or prove the upstream timing correct.
That remains a mandatory media/compositor check before any production use.

The planner is local and deterministic. It performs no image upload, network
request, external vision inference or paid generation. The current source-feature
record comes from local human inspection, not a claim of automatic vision. These
are hash-bound review assertions, not independently proven pixels or authenticated
review records. A future worker must load trusted saved review records; it must
not accept client-invented capability flags as authority.
Automating that stage later requires a reviewed implementation and any necessary
external-processing authorization. No extra controls or manual timeline are added
to the father's interface by this protocol.

Use same-original start/end anchors where the selected provider supports them.
A textual camera limit is a request, not a guarantee. Preserve request IDs, exact
settings, input/output hashes and anchor usage. Check the actual full clip for
identity/pose preservation, camera bounds, semantic action, eye behavior and
continuous unique motion. The complete film also needs variety, transitions,
source order, captions and audio review. A prompt alone never passes these checks.

The provisional camera-change bound and technical scene-duration ceiling are
explicit in the draft source; neither implies an approved aesthetic or tested
long-scene continuation. Source capabilities cannot silently become permission to
upload or spend. Missing features or changed hashes fail before provider work.

## Approval and changes

Missing settings, stale compilation, modified protocol/code or mismatched source
hashes fail closed. Revisions require a new draft version and regression review.
Keep approved presets immutable when one eventually exists. Only explicit approval
of a particular reference film, voice and settings can create that approved release.
No new final approval is inferred from encouraging but qualified feedback.
